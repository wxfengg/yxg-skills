# 接入验证与交付

验证分层，不用一种证据替代另一种。保持用户已有测试框架、构建工具与锁文件惯例；不为验证自动安装新框架。

## 本地必须尽力完成

- 确认安装来自选定 tgz、版本／指纹匹配、锁文件可复现；TypeScript import 来自五个公开入口，业务不引用 dist hash chunk 或内部 src。
- 用目标项目已有类型检查／最小构建验证实际接入文件。TypeScript 不使用 skipLibCheck／any 去掩盖新的合同问题。
- 验证初始化并发／迟到创建清理、登录切换不写旧 Store、监听释放、订阅 ready、发送失败与 evidence、已有同步 facade 的语义没有被改成 Promise。
- 断线后应重新 SUBACK，再收发一条新的消息，不能只看到 connected 就判恢复；destroy 后无新重连／旧回调。按业务采用的前后台策略检查恢复。
- 微信检查最终开发／发行输出的延迟 MQTT 加载、桥路径和必要的局部 navigator 绑定；不能仅凭 Node import 通过。
- 原生桥验证 ACK、epoch、独占实例和 retire/destroy；缺桥不编造实测结果。

维护者源码具备 `npm test` 和 `npm run verify:release -- /path/package.tgz`：后者会隔离解包、严格 NodeNext/Bundler 类型检查、Vite 生产构建、微信加载探针及 Chrome 原生 WebSocket+本地协议测试。它需要本机已有 Chrome 和 TypeScript（可用 CHROME_PATH/TSC_PATH 指定）；不是每个消费项目的必装工具，不要只复制命令就假设 scripts 随包存在。

## 外部环境最小动作

只使用授权测试身份、测试回环或确定无副作用的业务查询。

1. 目标环境首次加载、连接、SUBACK、安全发送和收到新消息；记录包指纹和实际工具／设备版本。
2. 断网后恢复，订阅恢复并能继续收发；重复 connect／反复进入页面不增连接。
3. 前后台／锁屏和退出／换账号，无旧身份回调或遗留重连。
4. 若有专用测试权限，验证认证／订阅拒绝；不修改生产 ACL 或试错真实账号。
5. 已提交但无确认时保持 unknown，不自动跨通道或新会话补发；若难以命中时机，如实记录未覆盖。

不能控制手机动作时，只给与本次接入相关的具体步骤，不反复要求用户重测已确认的同制品同环境证据。没有真实配置时完成本地接线／构建，单独指出真实服务待验。不要把本地 MQTT 报文对端称为完整 Broker，也不要把 0.1.0 编号解释为所有平台正式支持。

## 输出

简洁列出：改动文件及调用点、版本／制品、平台和所有者选择、关键行为差异、运行的命令／实际结果、尚未执行及原因。更新项目已有集成文档和必要记录，保留原回退制品／锁文件信息。若启动了临时服务，停止自己创建的进程并说明；无需接管用户原有服务。
